# 双核食堂 · DualCore Canteen

> 一道数学题、一道编程题，答对才解锁补给台。
> 补给必须同时满足营养需求和预算——而**营养数据直接就是游戏数值**。

单文件网页 · 零依赖 · 双击即玩 · 营养数据接麦当劳 MCP

---

## 一句话

**别的作品用营养数据做展示，这个作品拿它当战斗属性。**

- 蛋白质 → **ATK 攻击力**（×2）
- 脂肪 → **DEF 防御力**（×1.5）
- 碳水 → **HP 上限**（×2）
- 钠 > 2000 mg → 触发「口渴」DEBUFF，**ATK −20%**

你要过的三关，每一关都是「先答题，再配餐」：数学核与编程核都得答对，补给台才解锁；配出来的餐必须同时命中该关的**营养区间**和**预算上限**。配错了不是「提示一下」——直接过不了关。

---

## 为什么做这个

学习类作品常常是「打卡 + 积分」，饮食类作品常常是「查询 + 下单」。两边都很工具化，没人把二者放进同一个闭环里。

但真实的学生生活就是这样：**你在图书馆坐了一下午，饿了出来吃一顿麦当劳，然后回去继续。** 吃饭不是奖励，是补给——它决定你还能不能继续。

所以这个作品把「补给」做成了真的：你答对题换来一次补给机会，你选的餐决定你下关的血量和攻击。**吃得太咸会掉攻击力**不是一句玩笑话，是钠真的超过 2000 mg 时 ATK 乘 0.8。

## 快速开始

### 直接玩（5 秒）

双击 `dualcore_canteen.html`。内置离线演示数据，三关完整可通。

### 接真实 MCP 数据

```bat
set MCD_MCP_TOKEN=你的token
python tools/sync_nutrition.py
```

再打开 `dualcore_canteen.html`，右下角标签会从「○ 离线演示快照」变成「● 麦当劳 MCP 实时」。

> 只要 Python 3.9+，**不装任何第三方包**。`tools/mcd_mcp.py` 是纯标准库实现的 MCP 客户端。

## 玩法

| 关卡 | 目标 | 预算 |
|---|---|---|
| STAGE 1 · 起手式 | 热量 500–800 kcal，蛋白质 ≥ 25 g | ¥30 |
| STAGE 2 · 拉锯 | 热量 ≤ 900 kcal，蛋白质 ≥ 40 g，钠 ≤ 1500 mg | ¥45 |
| STAGE 3 · 终局 | 热量 ≤ 1100 kcal，蛋白质 ≥ 55 g，脂肪 ≤ 45 g | ¥55 |

**流程**：答两题 → 补给台解锁 → 点餐品加入餐盘 → 右侧实时显示是否达标 → 全部打着 → 「上菜 · 结算」→ 过关，双核 HP 上限提升。

答错会扣 HP：数学错扣数学核 12 点，编程错扣编程核 12 点。HP 归零不会立刻失败，但补给回血变慢——你得靠吃回来。

## 技术说明

| 项 | 方案 |
|---|---|
| 形态 | 单个 HTML 文件（内联 CSS + JS + 营养数据） |
| 依赖 | **零**。无 CDN、无框架、无构建 |
| 渲染 | 原生 DOM，无虚拟 DOM |
| 数据注入 | 营养数据内嵌为 `<script type="application/json">`，由 Python 脚本刷新 |
| 为什么内嵌 | `file://` 下 `fetch()` 会被 CORS 拦；内嵌才能双击就玩 |
| 题库 | 数学（定积分 / 求导 / 极限，高数基础）+ Python 基础语法 |

## 已知限制

1. 离线演示数据是**近似值**，界面会明确标注「○ 离线演示快照」，不冒充官方实时数。
2. 题库只有 12 道（6 数学 + 6 编程），够通三关，不够长期刷——这是刻意的，它是作品而不是题库产品。
3. 营养换算是**游戏化设定**（蛋白质×2 等），不是营养学模型，别当真的健身建议。
4. 不做下单。这是双核养成，不是点餐工具。
